# Публикация и сборка документов OPLA

**Русский** · [English](release.en.md)

Редакция 25.10.2026. Этот документ относится к **публичному GitHub** `zackshal/opla-security-lab`. Текущая основная ветка на момент подготовки материалов — `main`, коммит `bca6d66`. Ветка `docs/opla-student-materials-20261025` предназначена для переноса документации и не объединена с `main` до проверки Pull Request.

## 1 История и границы публикации

Публичный GitHub и рабочий GitLab имеют разные истории. Я переношу только проверенные файлы документации из коммита `66a003a`, не выполняя merge/cherry-pick его предков. В истории рабочего репозитория встречался закрытый `docs/teacher-key.md`; **его содержимое, старые коммиты и PDF с ответами не должны попадать в публичный GitHub**. Правило `.gitignore` не удаляет секреты из истории. Проверку публичной истории и подготовленных изменений выполняют отдельно до отправки ветки.

Не публикуются: `docs/teacher-key.md`, `OPLA_Teacher_Key.pdf`, `.env`, приватные ключи, образы qcow2, базы данных, пароли, сырые пользовательские журналы и неотобранные дампы. PDF и временные изображения создаются в игнорируемом `release-artifacts/`.

## 2 Публичные PDF

В этом репозитории генератор собирает **только** `OPLA_Lab_Manual.pdf`, `OPLA_Engineering_Report.pdf` и `OPLA_Portfolio.pdf`. Сборка закрытого ключа преподавателя намеренно отсутствует в публичном генераторе. Для закрытого экземпляра используется отдельный приватный исходный комплект.

```bash
python3 -m venv .venv-docs
.venv-docs/bin/python -m pip install -r tools/requirements-docs.txt
make check-docs
make docs
ls -lh release-artifacts/public/*.pdf
```

Параметры оформления: A4, поля 30/15/20/20 мм, основной текст 12 pt, межстрочный интервал 1,5. Листинги и таблицы используют меньший шрифт. После сборки нужно визуально проверить схемы, переносы и таблицы: успешный процесс экспорта не гарантирует идеальную вёрстку. Исходниками остаются Markdown и SVG; PDF в Git не коммитятся.

## 3 Проверки и публикация

```bash
make check
make check-docs
git diff --cached --check
git status --short
git log -1 --oneline
```

Перед отправкой проверить состав индекса (`git diff --cached --name-only`) и отсутствие приватных материалов; затем зафиксировать документацию в отдельном коммите и открыть Pull Request к `main`. Не использовать `git push --force` и не переписывать авторство старых коммитов. Существующие GitHub Actions и Makefile стенда должны сохраняться.

## 4 Статус подтверждения

В рабочей интеграционной копии ранее пройдены 92 Python-теста (один skipped) и переносимый C packet harness. Это не означает, что те же тесты уже прошли в публичной ветке или что проверены kernel verifier, KVM, работающий Zabbix API и чистая установка. Исторические наблюдения и отсутствующие доказательства отдельно перечислены в [протоколе](run-protocol.md) и [матрице приёмки](acceptance.md).

Тег релиза не создаётся этим переносом. Перед присвоением версии нужны результаты проверок именно опубликованного коммита, визуальная проверка PDF и контроль отсутствия закрытых данных.
