# Преподавателю: как проверить лабораторную

## Подготовка

Используйте выделенный Linux-хост по [спецификации](test-host-spec.md).
Развёртывание выполняется по [README](../README.md#быстрый-старт).
Для занятия заранее подготовьте три role images, установите CLI и проверьте
лабораторию. Сохраните commit, реальные версии и ID стенда.

## Порядок демонстрации

| Вопрос | Команда или действие | Что оценивается |
|---|---|---|
| Какие узлы используются? | `opla lab list`, `opla lab status` | Объяснение ролей attacker/victim/client |
| Готовы ли гости? | `opla lab ready` | SSH/cloud-init; не подмена готовности процесса готовностью защиты |
| Подключён ли фильтр? | `opla xdp stats` | Режим XDP, счётчики, отличие attach от доступности HTTP |
| Работает ли IDS? | `opla ids status`, `opla ids test` | Обнаружение контрольного события; alert не равен блокировке |
| Как выполняется опыт? | Сценарий по методичке после проверки изоляции | Конечная нагрузка только на victim своей lab |
| Доступен ли сервис? | Непрерывные HTTP-пробы с client | Коды, задержки, интервалы потерь до/во время/после опыта |
| Что значит отсутствие метрик? | Остановка и возврат collector по ФОС | Отличие потери наблюдения от нулевой нагрузки |

Справка: `opla --help`, `opla help scenario`, `opla help report`.
CLI показывает состояние и результаты; готовых теоретических ответов он не выдаёт.

## Вопросы для устного объяснения

1. Почему нужен отдельный client? Он независимо проверяет доступность сервиса.
2. Почему SYN и HTTP-запросы не равны? Одно соединение обслуживает несколько запросов.
3. Что означает HTTP 429? Отказ HTTP-сервиса по ограничению частоты, не XDP_DROP.
4. Почему alert IDS не доказывает блокировку? Обнаружение и предотвращение проверяются отдельно.
5. Как влияет NAT? Клиенты с общим source IP могут совместно расходовать лимит.
6. Зачем отдельная management network? Управление отделено от фильтруемого трафика.

Полные задания и тест: [ФОС](fos.md). Закрытый ключ к тесту передаётся отдельно.

## Оценка результата

Оператор сдаёт заполненный [отчёт](report-template.md), команды, выводы,
исходные метрики и объяснение ограничений. Скриншот dashboard без времени,
lab ID и исходных данных недостаточен. Порог, режим XDP и длительность опыта
должны быть указаны. Баллы выставляются по согласованной преподавателем рубрике.
Критерии приёмки всей разработки: [матрица ТЗ](requirements-traceability.md).
