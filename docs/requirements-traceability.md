## 2 Что требуется для окончательной приёмки

1. Записать согласование темы и допустимого диапазона учебной сети.
2. Проверить лицензии точных пакетов и зависимостей, особенно дополнительных
   инструментов attacker, включая версию Nmap. До этого критерий «все средства
   open-source» не помечается PASS. Gmail факультативен и не нужен обязательной работе.
3. На отдельно разрешённом чистом хосте выполнить установку зависимостей,
   bootstrap, images, установку snapshot, create, ready, activate, scenario,
   IDS marker, client coverage, Zabbix evidence, восстановление и удаление.
4. Записать команды, версии, source/image hashes, UTC, exit statuses, независимые
   observations и скриншоты. Каждый отсутствующий шаг — NOT TESTED, ошибка —
   FAILED/BLOCKED; результаты нескольких lab не объединять.
5. Оформить студенческий отчёт, отдельный ключ, проверить подписи рисунков,
   таблиц и листингов, читаемость PDF и требования кафедры к ГОСТ 7.32.

Для создания/удаления VM, запуска контейнеров, изменения host networking и
живой почтовой отправки нужно явное разрешение на отдельный тестовый хост.
Текущий Debian-хост разработчика для этой приёмки не используется.

## 4 Сборка документов

```bash
make docs
make docs-teacher DOCS_PRIVATE_DIR=/tmp/opla-teacher
```

Нужны уже установленные локальные reportlab/Pillow из tools/requirements-docs.txt.
`make docs-deps` требует отдельного сетевого доступа. Студенческий PDF находится
в release-artifacts/public/OPLA_Lab_Manual.pdf. Локальный docs/teacher-key.md
исключён из Git и system snapshot; его нужно передать преподавателю отдельно
или восстановить из приватного backup перед сборкой ключа. Проверяйте отсутствие
ключа в передаваемом студентам архиве. Старые PDF/DOCX в каталоге docs являются
историческими файлами и не заменяют свежий экспорт этой редакции.
