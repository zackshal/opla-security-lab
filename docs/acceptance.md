# Матрица проверок и доказательств

**Русский** · [English](acceptance.en.md)

Матрица задаёт критерии, а не объявляет новый успешный прогон. Наблюдавшиеся результаты и ограничения указаны в [README](../README.ru.md); версии — в [описании окружения](versions.md). Результаты другого проекта или прежнего commit не заменяют проверку этой редакции.

| Область | Что проверять | Достаточное доказательство |
|---|---|---|
| Portable | `make check` | Полный вывод, число тестов, skips, commit и среда; C harness не является kernel verifier |
| Документы | `python3 tools/check-docs.py` | Языковые пары и локальные ссылки; это не проверка истинности всех утверждений |
| Конфигурация и BPF | Jobs текущего [workflow](../.github/workflows/check.yml) | Успешные validators, compiler/package metadata и SHA-256 object для того же commit |
| Образы и установка | Подготовка с нуля по [инструкции](../README.ru.md) | URL/hash образов, package manifest, полный журнал; известная граница Suricata/backports сохраняется до повторного опыта |
| Изоляция | Выбранные LAB_ID, routes и scoped firewall | Проверка запрещённых направлений и положительная контрольная проба; один файл конфигурации недостаточен |
| XDP | Build, verifier, attachment и maps | Режим native/generic, аргументы сборки, program/maps и before/after counters |
| SYN и scan policy | Одинаковая конечная нагрузка при выбранных режимах | Параметры генератора, counters, trusted sources, окно и ответы независимого клиента |
| HTTP и IDS/IPS | Нормальный запрос и выбранный запрещаемый запрос | HTTP 200 как контроль; для IPS — связанный EVE SID и blocked delta; HTTP 000 сам по себе не доказывает IPS |
| Мониторинг | API, heartbeat, timestamps и данные | Актуальные объекты из [каталога](../monitoring/catalog.py), свежие значения и история Problems; старые item counts не переносятся автоматически |
| Уведомления | Problem и recovery, очередь, SMTP и получатель | Запись доставки и подтверждение получателя; SMTP accepted и inbox delivery различаются |
| Восстановление | [Snapshot, disk и DB workflows](backup-restore.md) | Проверенные операции над своим LAB_ID, сохранность данных и прикладная проба после восстановления |
| Развёртывание | [Ansible на целевом хосте](deployment.md) | Успешное применение и проверка сервиса на этом хосте; syntax-check недостаточен |

## Протокол отдельного опыта

Запишите commit, дату и часовой пояс, LAB_ID, host/guest kernel, image hashes, версии пакетов, интерфейс и режим XDP, параметры нагрузки, ожидаемый и фактический результат. Сохраните команды, коды завершения, before/after и контрольный HTTP-запрос. Для restore отдельно укажите восстановленную точку и возможную потерю более новых данных.

Результаты разделяйте на «пройдено», «ошибка», «пропущено» и «не выполнялось». Не называйте hosted CI проверкой KVM, live dashboard или восстановления хоста. Артефакт BPF с контрольной суммой не является криптографической подписью происхождения.

Локальные отчёты хранятся в `reports/` вне Git. Перед приложением доказательств к релизу исключите credentials, raw mail, private inventory и персональные сведения согласно [политике данных](data-lifecycle.md). Публичная демонстрация сохранённого вывода остаётся replay, а не записью нового опыта.
