# Завершение и сдача OPLA

Цель — завершить проверяемую учебную работу по ТЗ. Новые платформы,
полностью rootless backend и дополнительные интеграции не входят в этот
минимальный маршрут сдачи. Сначала закрывается существующий опыт с тремя ВМ.

## 1. Готовые материалы

- [x] README с назначением, архитектурой, требованиями и последовательностью запуска.
- [x] Методичка, схемы, ФОС и шаблон отчёта.
- [x] Автономные тесты и отчёт с явными пропусками и ограничениями.
- [x] Сборка публичных PDF и отдельный путь для приватного ключа преподавателя.
- [x] Документация установки, диагностики, резервирования и восстановления.

Эти отметки подтверждают наличие и проверку материалов, а не полную приёмку
стенда. Фактические результаты: [аудит](verification-2026-10-31.md).

## 2. Что необходимо закончить

| Этап | Действие | Критерий завершения |
|---|---|---|
| Публикация | Применить подготовленный commit и отправить отдельную ветку в GitLab | Remote содержит commit; pipeline просмотрен, причины skipped зафиксированы |
| Хост | Выбрать отдельный допущенный Linux x86_64-хост с KVM и ресурсами | Выполнены требования [спецификации](test-host-spec.md); область изолированной сети определена |
| Установка | Выполнить подготовку, images, trusted install, create, ready, activate | Три роли работают; сохранены версии, hashes, состояние сети и защитных механизмов |
| Опыт | Провести конечный сценарий и непрерывную проверку HTTP с client | Есть согласованные по времени XDP, EVE и HTTP evidence; пробелы явно отмечены |
| Восстановление | Выполнить согласованные сбои и recovery/backup drill | Измерено время восстановления, проверена сохранность данных и работа защиты |
| Сдача | Заполнить отчёт, проверить лицензии точных сборок, передать ключ отдельно | Закрыты шесть критериев ТЗ, тема и комплект согласованы с преподавателем |

## 3. Порядок работы без повторной переделки

1. Сохранить рабочие изменения и применить commit в отдельной ветке.
2. От обычного пользователя выполнить `make check` и проверку документации.
   Разобрать каждый пропуск; ошибки не превращать в PASS.
3. На выделенном хосте следовать [быстрому старту](../README.md#быстрый-старт)
   и [методичке](methodology.md). Не запускать повторный create после сбоя без
   проверки оставшихся ресурсов.
4. Вести один [протокол опыта](run-protocol.md) для одного commit и lab ID.
   Исторические снимки из README не подставлять вместо новых результатов.
5. Заполнить [шаблон отчёта](report-template.md), сверить
   [матрицу ТЗ](requirements-traceability.md), собрать `make docs`.
6. Перед сдачей проверить PDF, приложение исходников и отдельную передачу
   преподавательского ключа. Образы/PCAP передавать отдельно с SHA-256.

## 4. Граница текущего результата

В среде проверки GitLab недоступен по DNS; отправка и remote pipeline не
подтверждены. QCOW2 в исходном архиве отсутствуют, новый live-прогон не выполнен.
Правила `AGENTS.md` требуют отдельного допущенного хоста для операций с VM и
сетью. Автономная проверка готова; оставшиеся live-этапы требуют этого хоста.
