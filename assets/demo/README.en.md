# Recording the current interface

[Русский](README.md) · **English**

terminal-replay.gif/mp4 is a historical replay of saved output. Do not relabel it as a recording of current Zabbix or use a staged UI as evidence.

Record the real screen after checking the active LAB_ID and data freshness. Hide credentials, email addresses, private inventory and unrelated tabs. Record commit, date/time zone and selected time range. Clearly identify historical events as history.

Suggested sequence: current host selection → fresh values and heartbeat → actual dashboard pages → Problems and one expanded event → recovery/normal state. Do not generate traffic merely for video without a separate bounded test procedure. A screenshot alone does not establish a mechanism's effectiveness.

Four to six screenshots or a short recording are sufficient for review. Use actual page names and item counts, not the old 28-item guide. Distinguish XDP, HTTP, Suricata, passive scan and notification queue data.

Add reviewed media under assets/demo and then switch README to the existing new files. Until real frames are available, do not invent screenshots, values, nonexistent video links or a claim that the demo is updated.
